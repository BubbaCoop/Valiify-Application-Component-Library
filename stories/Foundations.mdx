# Design Tokens

Extracted from Figma `Updated-Short-App` (fileKey `PA5pr1Q8KLfbjTxdAbFm0V`).
Colors, spacing and radii come from a **complete Plugin API enumeration of the
local variable collection** (all 77 variables, applied or not — the
applied-only sweep had missed 26 unapplied colors including the entire Error
and Info ramps); typography comes from the type-preview section (1:2) plus
component sweeps. This page exists to be compared side by side with the Figma
variables panel — every swatch and specimen below should match.

Tokens live in a Tailwind `@theme` block in `src/themes/valiify.css`, which is
**generated** from `tokens/figma-tokens.json` by `scripts/build-theme.mjs`.
Regenerate with `npm run build:theme`.

Colors are stored as OKLCh; the hex shown here is the original Figma value. The
generator asserts every conversion round-trips back to its source hex within
1/255 per channel, so the two are equivalent.

> **Two naming mappings, deliberate:** Figma's `Text/*` group emits as
> `--color-content-*` and `BG/*` as `--color-surface-*` — avoiding
> `text-text-secondary` / `bg-bg-paper` utilities and matching the dashboard
> library's public API shape. A ramp's main shade is unsuffixed whether Figma
> calls it `Primary/Primary` or `Neutral/Base`.

## Focus ring

Figma's **Primary Ring** effect: a spread-only drop shadow — offset 0/0, blur
0, spread **3px**, in `Primary/Ring` (`#a6192e38`, primary at 22% alpha).
Available two ways:

- the `focus-ring` utility (an outline at offset 0 — same geometry), applied on
  `:focus-visible` by every interactive component
- `--shadow-focus-ring` → `shadow-focus-ring` where a real box-shadow is needed

## Radii

Figma's radius scale uses Tailwind's own t-shirt naming, and the values are
emitted verbatim:

| Token | px | vs Tailwind v4 default |
| --- | --- | --- |
| `--radius-xs` → `rounded-xs` | 2 | identical |
| `--radius-sm` → `rounded-sm` | 4 | identical |
| `--radius-md` → `rounded-md` | 6 | identical |
| `--radius-lg` → `rounded-lg` | 8 | identical |
| `--radius-xl` → `rounded-xl` | 10 | **overrides** (Tailwind: 12) |
| `--radius-2xl` → `rounded-2xl` | 12 | **overrides** (Tailwind: 16) |

`Radius/none` (0) and `Radius/full` (9999) are not re-emitted — native
`rounded-none` / `rounded-full` already mean exactly that. The xl/2xl
overrides are deliberate: `rounded-xl` should mean *this design system's*
corner, and xs–lg matching Tailwind's defaults exactly suggests the designer
built on Tailwind's scale on purpose.

## Spacing

13 whole-px variables — 2, 4, 6, 8, 10, 12, 16, 20, 24, 32, 40, 48, 64 —
**every one mapping exactly to a native Tailwind step** (`Spacing/2` → `p-0.5`,
`Spacing/8` → `p-2`, `Spacing/64` → `p-16`: divide by 4). So no `--spacing-*`
tokens are emitted, same rule as the dashboard library — defining
`--spacing-8: 8px` would make `p-8` mean 8px instead of 32px.

## Border widths

No stroke-width variables exist in the file; stroke widths are raw per
component (Radio's ring is an authored 1.5px, for example).
